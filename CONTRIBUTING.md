# Contributing

Thanks for helping. abacus is pre-1.0, so open an issue before a large change; small fixes can go
straight to a pull request. By taking part you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).
Security problems go through [SECURITY.md](SECURITY.md), never a public issue.

## Build and check

You need Go (the version `go.mod` names; see [docs/development.md](docs/development.md)).

```
make help         # every target
make build-dev    # quick build with no tools built in: bin/abacus
make check        # gofmt, vet, shellcheck, tests, tagged-build check
```

`make build` (every tool inside the binary) needs `gh`, `npm` and `bun` and is for releases; you
do not need it to work on abacus. `shellcheck` is needed for `make check` (hosted CI runs it too).

## Test isolation rules

- Run tests with an isolated `HOME` and `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME`
  (a temp dir) and a private `GOCACHE`. Never point a test, or yourself while developing, at a real
  tracker, hub, supervisor or board.
- Tests use fakes, fixtures and temp directories. The only real tool the tests run is `bd`, against
  a temp project, and they skip when it is absent. Nothing launches an app or takes window focus.
- Test data uses invented names (`bot-scheduler-01`, `fixture-user`, `dm-zoj`); do not paste real
  hostnames, user names, tokens, task ids or paths into code, fixtures or goldens.

Run the suite with isolated state, cache, and temporary files. Choose a disk-backed directory for `abacus_scratch_root` if your usual cache is in memory.

```bash
abacus_scratch_root="${XDG_CACHE_HOME:-$HOME/.cache}/abacus-tests"
mkdir -p "$abacus_scratch_root"
abacus_scratch=$(mktemp -d "$abacus_scratch_root/run.XXXXXXXX")
mkdir -p "$abacus_scratch"/{home,config,state,data,cache,tmp,gocache}
HOME="$abacus_scratch/home" XDG_CONFIG_HOME="$abacus_scratch/config" \
  XDG_STATE_HOME="$abacus_scratch/state" XDG_DATA_HOME="$abacus_scratch/data" \
  XDG_CACHE_HOME="$abacus_scratch/cache" TMPDIR="$abacus_scratch/tmp" \
  GOTMPDIR="$abacus_scratch/tmp" GOCACHE="$abacus_scratch/gocache" \
  go test -count=1 ./...
```

## Architecture rules

- Logic lives in `internal/core` and `internal/taskview` as pure code with typed JSON
  (`schema_version` 1; changes are additive only). The CLI and TUI are thin; terminal UI libraries
  are imported only in `internal/tui`.
- Every write goes through the existing gate: plan, confirm, single-use apply, fail-closed audit,
  exact argument allowlists, scrubbed environment. A timeout or cancel is "result unknown", never
  "not applied". Do not add a path around it.
- Use domain names in navigation and keep provider names in connection help and Doctor.
- TUI changes update the goldens with the harness (`go test ./internal/tui -update`) and you read
  the diff; look at the result in a terminal at a narrow and a wide size.

## Licensing

abacus is GPL-3.0-or-later (see `LICENSE`). Source files carry no per-file license header: the
repository-level `LICENSE` and `THIRD_PARTY_NOTICES.md` (generated by `make build` from the pinned
tools; `abacus licenses` prints it) are the notice. Contributions are accepted under the same
license. A new dependency or built-in tool needs a compatible license and an entry in
`docs/built-in-tools.md`.

## Commits and pull requests

- Small commits with a gitmoji prefix and a short subject, in the style of `git log`
  (for example `🐛 core: ...`, `✅ tui: ...`, `📝 docs: ...`). Name files explicitly when staging.
- Update `CHANGELOG.md` under `[Unreleased]` for anything a user can see.
- Open a pull request against `main` (a draft is fine). It should say what changed and why, how you
  verified it, and what you did not. CI must pass: `gofmt`, `go vet`, `shellcheck` and the tests.
- Keep a change to one purpose; behavior changes and refactors go in separate pull requests.

Design notes and plans live in [docs/design](docs/design/); the docs index is [docs/README.md](docs/README.md).
